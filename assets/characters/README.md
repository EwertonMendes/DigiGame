# Character Sprite Provenance

DigiGame contains legacy prototype character art from commercial Digimon games. These sprites are **not** open-source assets.

The normalized runtime sheets used by the current battle scene are committed to the repository. A clean checkout therefore does not have to contact sprite-hosting sites before the game can run. The old fetch/preparation scripts remain only as optional provenance/reproduction tools and are no longer part of normal Web CI.

Every `directional_12` sheet follows one complete runtime contract: `down_left`, `down_right`, `up_left`, `up_right`, with `idle`, `step_a`, `step_b` inside each direction. The original DS sheets do not all store those groups in the same authored order. `database/ds-direction-review-map.json` therefore classifies the source layout into reusable conventions, while `tools/materialize_ds_direction_registry.py` materializes every convention into the same canonical runtime order before Godot ever sees the asset. Runtime movement code does not check Digimon names, swap species-specific facings, or horizontally flip normalized `directional_12` sprites.

The current source conventions cover the observed combinations of row order and horizontal ordering: `canonical_rows`, `canonical_rows_rear_reversed`, `rear_rows_first`, `rear_rows_first_rear_reversed`, `compact_interleaved`, `compact_interleaved_rear_reversed`, and `compact_interleaved_horizontal_reversed`. Each convention has a regression representative in the review map. A species selects a source convention as data because its original authored sheet uses that layout; the runtime contract remains identical for every species.

Higher-rank DS additions are normalized through the same principle in `database/ds-additional-sources.json`. Their source-specific layout is represented as reusable data before the canonical strip is generated. Structural profiles describe where the authored movement cells live, while direction patterns describe their semantic order. Profiles may restrict extraction to a normalized region of the sheet when credits or unrelated poses share the same rows; this is source-structure data and does not create runtime species branches. The Agumon- and Garurumon-line additions therefore all materialize into the exact same `directional_12` contract.

War Greymon's four movement rows preserve the compact interleaving of front/rear poses but have left/right authored in the reversed horizontal order, so the existing `compact_interleaved_horizontal_reversed` convention (`[2, 0, 3, 1]`) is reused to produce the normal `down_left`, `down_right`, `up_left`, `up_right` runtime contract. This remains a source-normalization rule only; runtime code contains no War Greymon-specific flip or facing branch.

Omnimon is named `Omegamon` in the audited With the Will source archive. DigiGame keeps the canonical database/display name `Omnimon`, while the pinned source provenance points to `sprite thread/313_Omegamon.png`. AncientGarurumon's archive member has no numeric prefix, so its source identifier is intentionally null while its exact archive path and SHA-256 remain pinned.

Walk phases are normalized by one global policy as well. The authored left-facing triples define `idle`, `step_a`, `step_b` in source order. For each corresponding right-facing triple, the materializer evaluates every three-frame permutation and chooses the deterministic best match against horizontally mirrored left-facing poses. Per-species phase overrides are forbidden by schema validation. The resulting exact coordinates, selected phase order, pixel error, confidence margin, source hash, and bottom-center anchor are recorded in generated field metadata.

Agumon, Greymon, MetalGreymon, and Mochimon remain separately preserved reviewed references where required by their source ownership. The complete Fresh/In-Training/Rookie WtW roster is otherwise rebuilt from pinned original source hashes through `database/ds-direction-registry.json` into each character's committed `field.png` and `field.json`.

Mochimon uses the project owner's September 20, 2026 directional sheet rather than the previous single-pose community fallback. The 1877x838 source canvas is treated only as authoring input: the blue/cyan canvas is removed, the reviewed movement poses are normalized with nearest-neighbor resampling into the existing 52x49 runtime cell contract, visible sprite bounds are capped at 48x46, and every frame is bottom-center anchored. The supplied sheet has authored down-right and both rear-facing triples; the missing down-left triple is created once at build time by horizontally mirroring the matching down-right poses. The committed `field.png` is therefore already canonical `directional_12` data and renders at native scale `1.0`; runtime code contains no Mochimon-specific flip, size override, or workaround. Its normalized output hash is pinned in `assets/characters/mochimon/field.json` so source rebuild tooling cannot silently replace it.

Koromon and Tanemon originate from the With the Will sprite archive used by this prototype. Their source sheets use different authored direction-group conventions, represented explicitly in the semantic review map rather than by runtime mirroring or species-specific movement code. Gabumon likewise uses a different compact authored order while still producing the exact same canonical runtime contract.

Veemon uses the latest transparent spritesheet supplied directly by the project owner in the September 9, 2026 correction pass. The current runtime file is `assets/characters/veemon/field.png` and uses the `spaced_9_32` runtime layout: nine 32x32 cells separated by one transparent spacer column. It must not be sliced with `Sprite2D.hframes = 9`; the runtime crops each exact 32x32 cell at a 33-pixel stride. The right-facing variants are horizontal mirrors of the corresponding supplied left-facing walk frames.

MetalGreymon uses the Digimon World DS sheet listed as asset `48322` on The Spriters Resource, with the project owner's With the Will / historical Photobucket link as the original reference. The exact downloaded source used for the September 12, 2026 extraction is 395x432 and has SHA-256 `2f370926a0585787dfbae2b575509f8698a80539c8a68c87d3586b1d99a05665`. A second inspection pass found all twelve authored small field frames in that sheet: two three-frame front-facing columns and two three-frame rear-facing columns. `tools/fetch_metalgreymon_field.py` extracts those four directions directly and writes `assets/characters/metalgreymon/field.png` as a clean 12-cell `directional_12` sheet. No frame is mirrored, resized, repainted, or color-keyed; the purple credit panels and watermarks sit outside the exact alpha-backed source boxes.

`tools/validate_runtime_assets.py` verifies all battle-critical committed character sheets together with the terrain, VFX, and UI fonts without making network requests. DS rebuild validation additionally proves the declared source conventions, generated metadata, phases, anchors, exact source coordinates, and pinned source hashes. Separate manifest-driven Godot regressions exercise every additional DS species through canonical facings in battle actors, overworld followers, menu walk previews, and packaged portrait assets.

Rights to Digimon and the official game artwork remain with their relevant Digimon/Bandai Namco rights holders. No free-content license is claimed. These assets are suitable only for the current fan/prototype context and should be replaced by original or properly licensed artwork before commercial distribution.
